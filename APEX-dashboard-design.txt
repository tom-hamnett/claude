APEX PMO — Data Visualisation & Dashboard Design
=================================================
Prepared for: Tom Hamnett / Sopan Shah (CPO)
Design approach: Senior strategy consulting / data storytelling
Framework: Embedded in APEX (React + Recharts), not external Power BI


THE PRINCIPLE
-------------

A CPO doesn't want a dashboard. He wants answers.

"How is the programme doing?" → one glance.
"Why is it doing that?" → one click.
"What do I do about it?" → one more click.

Everything below follows the Pyramid Principle: answer first, evidence second, detail third. Every visualisation earns its place by answering a specific question a senior stakeholder would ask. If it doesn't answer a question, it doesn't exist.

Visualisation choices and WHY:

- KPI cards with RAG: instant status at a glance. No cognitive load.
- Progress bars (not pie charts): humans read linear progress better. Shows actual/target.
- Area charts for spend: shows trend AND magnitude. Fill conveys volume.
- Stacked bars for P2P: shows composition (which regions contribute) AND total.
- Scatter plot for suppliers: two dimensions (risk × performance) in one view. Quadrant analysis.
- Ranked list for risks: not a chart — risks are best as a prioritised list with RAG dots.

Filter bar is KEY. The CPO asks "show me AMER only" or "just Q1 2026" — one click.

Visualisation choices:

- Sparklines in KPI cards: show trend without taking space. The number is the answer, the sparkline is the context.
- Multi-series area chart: shows how multiple dimensions (regions, categories) contribute to the total over time.
- Waterfall chart: explains WHY a number changed. "Spend went up $8M because AMER +$12M, EMEA -$4M." This is the chart consultants use to tell the story.
- Heat map: shows coverage/completeness across two dimensions. Instantly reveals gaps. "We have no supplier data for APAC food & beverage."
- Bullet chart: actual vs target with qualitative ranges (good/ok/poor). More information-dense than a simple bar.

CHART TYPE DECISIONS
--------------------

Rule: the chart type is chosen by the QUESTION, not the data.

| Question pattern                        | Chart type          | Why                                    |
|-----------------------------------------|---------------------|----------------------------------------|
| "What's the number?"                    | KPI card            | Just show the number. Big. With RAG.   |
| "What's the trend?"                     | Sparkline or area   | Time on X, value on Y. Simple.         |
| "How does it break down?"              | Stacked bar / donut | Composition. Parts of a whole.         |
| "How do two dimensions relate?"        | Scatter / bubble    | Correlation. Outlier detection.        |
| "Why did it change?"                   | Waterfall           | Attribution. Bridge from A to B.       |
| "Where are the gaps?"                  | Heat map            | Coverage matrix. Spot the blanks.      |
| "Are we on target?"                    | Bullet chart        | Actual vs target vs ranges.            |
| "What's the distribution?"             | Histogram / box     | Shape of the data. Outliers.           |
| "What are the priorities?"             | Ranked list         | Not everything needs a chart.          |

NEVER use:
- 3D charts (distort perception)
- Pie charts with >5 slices (unreadable)
- Dual-axis charts (confusing, always misleading)
- Gauges/speedometers (waste of space, low information density)


COLOUR SYSTEM
-------------

Use APEX's existing dark theme palette:

- Primary metric: var(--accent) (#2ABFBF) — teal
- Positive/on-track: #5DC484 — green
- Caution/at-risk: #F5C544 — amber
- Critical/off-track: #E8734A — red/orange
- Neutral/reference: var(--text3) — muted grey
- Dimension series: 5-colour qualitative palette
  - #2ABFBF (teal)
  - #9B7FE6 (purple)
  - #F5C544 (gold)
  - #E8734A (coral)
  - #6BB8E0 (sky blue)

Sequential data (e.g. spend magnitude): single-hue gradient from light to dark teal.
Diverging data (e.g. above/below target): green ← grey → red.


POWER BI VS EMBEDDED RECHARTS
------------------------------

Recommendation: BUILD IN APEX using Recharts. Do NOT use Power BI Embedded.

Reasons:
1. Power BI Embedded requires a Power BI Pro licence ($10/user/month) AND a dedicated capacity ($700+/month for A1 SKU). Free tier doesn't support embedding.
2. Recharts is already in the stack. No new dependencies.
3. Embedded charts share the same auth, theme, and state as the rest of APEX.
4. Filter interactions can directly update the AI chat context — "I'm looking at AMER Q1 spend" feeds into the AI's awareness.
5. No iframe/embedding lag. Native React rendering.

The only reason to use Power BI would be if Sopan's team already uses Power BI and wants to see APEX data alongside other reports. In that case, APEX already exposes a REST API and Tableau WDC endpoint that Power BI can consume as a web data source. Both paths are available.

For the CPO demo: build it in APEX. It's faster, cheaper, and more impressive.
