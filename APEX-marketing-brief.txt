## 4. HOW IT WORKS — 5 STEPS

**1. Connect your sources**
Paste a SharePoint sharing link, or sign in with your Microsoft account via a one-time device code flow. APEX also connects to Google Drive, OneDrive, GCS, or any HTTPS endpoint. No IT ticket required for the basic path. [The Microsoft OAuth flow was built and tested in this thread.]

**2. APEX discovers and polls**
A scheduler polls your sources on a configurable interval (default: hourly). It detects new and changed files via content hashing — only changed files trigger re-ingestion. You see a pending ingestions queue showing exactly what's new.

**3. Dual-path ingestion**
Excel and CSV files are parsed into structured data tables with auto-detected column types, dimension detection, and version diffing against previous uploads. PowerPoint, PDF, and Word documents are text-extracted and stored in a persistent document library. Both paths feed the AI. [Multimodal image-based parsing for PowerPoint slides is planned but not yet built — Workstream 3.]

**4. AI knows your programme**
Every question you ask in the chat is automatically enriched with your full document library (up to 60,000 characters of source text injected server-side) plus the structured data visible on your current page. The AI cites filenames. No drag-and-drop, no re-uploading — it just knows.

**5. Structured outputs, not just answers**
The AI proposes structured changes — executive summaries, risk register entries, programme updates — that you accept or reject with one click. KPIs are defined against your data tables with configurable RAG thresholds, and gaps are automatically detected (stale data, missing dimensions, null values).

## 5. THE 5 INTEGRATED LAYERS

**Layer 1: CONNECT — Enterprise Source Integration**
Connects to SharePoint (anonymous links, org-internal links via OAuth, or IT-managed app registrations), Google Drive, OneDrive, GCS, HTTP endpoints, and uploaded ZIPs. The Microsoft OAuth flow uses device code authentication — the user signs in with their corporate credentials, APEX stores a refresh token, and all subsequent access uses the user's identity. No service accounts, no IT provisioning. Tokens refresh automatically.

**Layer 2: INGEST — Dual-Path Document Processing**
Excel/CSV files are parsed into structured data tables: column type detection (number, date, string), dimension identification (categorical columns with ≤30% unique values), and automatic version diffing when a file is updated. Non-Excel files (.pptx, .pdf, .docx) are text-extracted via officeparser and stored in a persistent document library. Both paths are triggered from the same pending ingestions queue — the UI distinguishes "DATA" files (gold) from "DOC" files (purple). [PLANNED: Workstream 3 adds multimodal parsing via Gemini, processing PowerPoint slides as images to capture colour-coded RAG status that text extractors lose.]

**Layer 3: STRUCTURE — Data Model & Gap Detection**
Structured data lives in versioned tables with full column metadata. KPI definitions link to source tables with configurable value columns, time columns, dimension columns, aggregation methods (sum/count/avg), targets, and RAG thresholds (green/amber). Data templates define expected shapes for recurring uploads, with automatic template matching on ingestion (percentage match score). Gap detection runs across all KPIs: missing source tables, empty data, stale data (>45 days), missing dimension coverage in the latest period, and null values in metric columns.

**Layer 4: INTELLIGENCE — AI Engine (Provider-Agnostic)**
Multi-provider LLM support: Anthropic (Claude), OpenAI, Azure OpenAI, Google Gemini, GitHub Models, and custom endpoints. Users configure engines in Settings — multiple can coexist, with one marked as default. The AI chat's system prompt is enriched server-side with the full document library (up to 60K characters, most-recent-first). The AI operates as a senior PMO advisor: it answers questions grounded in source data, proposes structured changes (executive summaries, risk entries, programme updates), and respects an explicit confirmation workflow — it never commits changes silently.

**Layer 5: PRESENT — Dashboard, Reporting & Integration**
React dashboard with KPI visualisation (Recharts), metric panels organised by domain and panel, data table browser with row-level inspection and CSV export. Tableau integration via a built-in Web Data Connector (WDC) endpoint — Tableau Desktop connects directly to APEX's API and pulls denormalised programme data. Per-domain Tableau feeds with metric metadata (target, direction, unit). Full audit log of all programme changes with before/after state.

## 11. AI ENGINE AGNOSTICISM — WHY IT MATTERS

APEX supports six LLM providers: **Anthropic Claude, OpenAI, Azure OpenAI, Google Gemini, GitHub Models, and custom API endpoints.** Users configure engines in Settings with their own API keys — multiple engines can coexist, with one marked as default.

**Why this matters for enterprise buyers:**

1. **AI policy is volatile.** Large enterprises are changing their approved AI vendors quarterly. If you build on ChatGPT and the CISO mandates Azure-only, your tool breaks. APEX doesn't — swap the engine in Settings, keep working.

2. **Different engines for different tasks.** [PLANNED for Workstream 2] Tom's architecture uses Claude for conversational chat (better at nuanced PMO reasoning) and Gemini Enterprise for multimodal document parsing (better at reading slide images). APEX supports this natively.

3. **Data residency.** Enterprise AI policies often mandate that data stays in-region. Azure OpenAI lets you choose deployment region. APEX passes through to whatever endpoint you configure — it doesn't route your data through a third-party proxy.

4. **No vendor lock-in.** If Anthropic raises prices or OpenAI changes terms, switch. Your data, your KPIs, your document library — all stay in APEX. Only the inference endpoint changes.

## 13. PROOF & HONESTY

**What's genuinely built and working (verified in this thread):**
- Full React + Express + SQLite application running in a GitHub Codespace
- 8 source connector types including SharePoint with OAuth device code flow
- Auto-polling scheduler with content-hash change detection
- Excel/CSV parser with column type detection, dimension identification, version diffing
- Document text extraction for .pptx, .pdf, .docx via officeparser
- AI chat with server-side document library injection (up to 60K chars)
- Multi-provider LLM support (6 providers configured)
- KPI engine with RAG thresholds and gap detection
- Tableau WDC integration
- Audit logging with before/after state

**What's planned but not yet built:**
- Gemini Enterprise as a second LLM provider for multimodal parsing (Workstream 2)
- Multimodal PowerPoint parsing — processing slides as images to capture RAG colour coding (Workstream 3)
- Production deployment on Azure App Service (currently Codespace-only)
- Enterprise SSO / RBAC
- Multi-programme portfolio view
- Deep recursive subfolder scanning (currently one level deep)
- Vector search / semantic retrieval (currently brute-force context injection)

**Honest limitations:**
- PowerPoint RAG colours (red/amber/green conveyed via cell/shape formatting) are **lost** during text extraction. The text content is captured but the visual status indicators are not. This is the primary gap that Workstream 3 addresses.
- The document library context window (60K chars) means very large document libraries will be truncated — most-recent-first. No semantic search to select the most relevant documents.
- Download URLs from SharePoint sharing links expire after ~1 hour. If a file is discovered but not ingested promptly, the user needs to re-sync.
- Currently single-tenant, single-user. No authentication on the APEX application itself.
