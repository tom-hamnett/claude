## KEY DECISIONS AND REASONING LOG

Decision: Multi-channel by default — every master asset generates ALL derivatives
Reasoning: A single insight is an asset, not a post. Channel strategy determines sequencing, not whether to deploy.

Decision: Separate audience development playbook per channel
Reasoning: Reddit, email, Instagram, LinkedIn each have fundamentally different growth mechanics. One strategy doesn't fit all.

Decision: Email lifecycle sequences before broadcast sends
Reasoning: Never batch-send to small lists. Lifecycle sequences outperform at every list size. Broadcast only when 500+ engaged subscribers.

Decision: Live Intelligence Feed as always-on input (not just stage gates)
Reasoning: Founder insights and market signals don't arrive on a schedule. The engine must be able to receive and act on them at any time.

Decision: Brand + Standards Module built BEFORE content generation begins
Reasoning: Without guardrails set first, content drifts from day one. Standards must exist before the factory runs.

Decision: Build order starts with Layer 8 (Brand Standards) before Layer 3 (Content)
Reasoning: You can't benchmark content quality against standards that don't exist yet.

Decision: SQLite first, Supabase later
Reasoning: Local dev is faster and easier to debug. Cloud infrastructure only when Layer 3 is solid.

Decision: Email deployment before social deployment
Reasoning: Cleanest API, best feedback signals, lowest rate-limit risk during testing.
